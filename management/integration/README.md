# Slate native core-wiki integration

This is a source-owned candidate for reviewed static adoption. It is not registered
in RER, not deployed, and not a first-party loader plugin. Generic admission uses
`rer-project.json` with the `project` trusted-build profile and an external exact
source SHA. The service retains authority over provider resource names, addresses,
configuration approval, previews and deployment. Slate retains native auth,
mailbox bootstrap, session validation, grants, D1/R2 storage and Worker handlers.

`deployment-spec.json` and `source-provenance.json` are generated by
`pnpm integration:sync` through the Base spec reader from emitted `dist/server/wrangler.json`, original migration
bytes and named native source inputs. `pnpm source:check` refuses drift. No setup
SQL is invented: the native `bootstrapOwner` creates an initial workspace only
for the configured mailbox after its sign-in flow, when no workspace exists.
No worker/database/object/queue names or credentials are baked into the recipe.
Core-wiki fixes `SLATE_PROFILE=core-wiki`, `AI_ENABLED=false`, `SSO_ENABLED=false`
and denies unsupported provider configuration. The retained collaboration class
and its applied DO migration remain present even though its socket is disabled.

The static factory (`index.ts` / `index.mjs`) implements the service's
`ProjectIntegration` contract retained in `contract.ts`. Preserve MIT licensing.
Generated app configuration uses one HTTPS host for `/signin`, `/app`, `/api` and
`/p/`. Preview plans require declared controlled providers and have no schedules
or queue consumers. Core data and native HTTP paths are not rewritten.

A service owner can export the committed directory through the service's
`integration-bundle.mjs` and review a static adoption. The source command below
exports and adopts only into a new scratch directory, invokes the actual service
candidate/plan/descriptor validators, validates production and preview shapes,
checks byte-identical SQL, tests refused profile changes and bundle tampering,
and leaves a JSON result. It never edits the service checkout or contacts a
provider. Run with Node 22.20.0 and the installed pinned tsx:

```sh
pnpm check:rer-adoption --service-root /absolute/read-only/service --output /absolute/new/scratch
```

For generic project admission, the owner must explicitly configure `APP_URL`,
`PUBLIC_PAGE_HOST`, `SETUP_OWNER_EMAIL`, `MAIL_FROM` and the declared native
secrets. Generic project admission does not invoke this static factory. Static
registry adoption is a separate service-owner change with its own verification.

The checked-in contract and source lock describe this source boundary. Service admission, trusted workflow pins and deployment must be verified separately.
