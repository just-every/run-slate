# Source analysis

The failing stack is not the outline assertions. `journeys.test.mjs:449–457` runs setupWorkspace, outlineJourney, settingsJourney and workspaceAuthorityJourney in a single new core-wiki workspace. `reading-journeys.mjs:100` calls statusVocabularyJourney at 1440px. `status-vocabulary-journey.mjs:35–45` opens its own Add/Edit status dialog, fills its controls, clicks Save status and retains the unchanged count-zero assertion. Line 77 retires the renamed status; this is the hosted failing call.

`StatusSettings.tsx:65–85` submits the vocabulary mutation and awaits resource.reload; `ActionDialog.tsx:63–65` closes after the submit resolves. Hosted timeline proves retirement POST /api/status succeeded in 16ms and its subsequent GET /api/status in 12ms. No rejection or browser console error was recorded. The server write was not observed waiting for five seconds; the remaining mounted dialog is a client-side symptom. Its root cause is not established by that receipt alone.

All seven relevant shared-source files (the registration, sharder, outline, status vocabulary, workspace/browser isolation, status UI and dialog UI) have identical Git blobs on fetched main and the candidate; shared-source-blobs.json records both object IDs. No new timeout or assertion edit is authorized without candidate causation.

The relation slice changes actual-record resolution, relation configuration's retained-target checks, one field tooltip and its dedicated relation journey. The relation journey is called by recordDetailJourney in a different top-level registration, not by the page-outline test. Browser-support creates a new D1 state directory copied from a pristine schema, starts a new runtime, opens a new browser/context and closes them in finally for each top-level workspace. withSecondPerson closes its context in finally. No shared page or status vocabulary survives across those workspaces. These source facts argue against an unclosed relation dialog or shared workspace state causing the page-outline failure; they do not exclude host-level contention.

The local comparison intentionally runs the exact page-outline test at 1440px using Node 22.20.0, pnpm 10.12.4 and /usr/bin/chromium, through the existing journey sharder and emitted Worker, twice per source SHA. It does not recreate the hosted parallel Worker shard, and four local passes cannot prove the absence of a hosted flake.

The first local candidate run passed both native status-vocabulary profiles, including status retirement and dialog closure, then exhausted the existing whole-test 600000ms deadline after the theme journey. Its outer 660-second bound returned 124; no process remained. This is a real failed local run, not a successful full test. Remaining comparisons are recorded separately.
