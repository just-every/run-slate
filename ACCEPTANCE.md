# Slate release profiles and retained full flagship acceptance

## Target contract acceptance — 16 October 2026

[CONTRACT.md](CONTRACT.md) now describes the whole category job a Confluence, Notion or Guru buyer needs: the 221 published clauses plus 105 target and push-further clauses. This section lists the acceptance evidence for every one of them and its status, so a build round can work towards them. The rules below this section are unchanged.

- **Acceptance evidence** names the journey or test, through a public door, that proves the clause. For a published clause, the clause is satisfied by a tagged Workers journey (`ID — …`) under `tests/e2e/` that `scripts/verify.mjs` counts, plus the browser, provider or release evidence the layers below require. A target clause is first registered (see CONTRACT.md, *How to read this contract*) and then proved the same way. Planned registration may retain its target heading; publication waits for a release that ships it, recorded in `RELEASE.json`.
- **Status** (`done`, `partial` or `missing`) is the build-planning judgment in CONTRACT.md's *Status* table in this revision. `done` means the default profile ships the behavior and a cited test exercises it. It is not acceptance: the evidence layers, the zero-tolerance rules and independent release verification below still apply. `tests/requirements/clause-inventory.json` keeps every published clause as unproven until that verification is done.
- **Default product.** Every target and push-further journey runs in the default profile with `SLATE_PROFILE` unset, with only the owner switches its clause names turned on (`ADMIN-007`). A journey that passes only under `SLATE_PROFILE=flagship` does not count for a target clause.
- **Fakes** are allowed only at a paid or network edge (AI, mail, push, chat, connector and identity providers). Fixture runs prove local semantics only; each provider-facing clause also needs provider acceptance against a real authorized account (layer 3).
