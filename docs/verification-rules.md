# Verification rule semantics

What the rules mean (each container has the three rules, all off by default): - **Who configures.** A container's owners, through the same authorization as the container's settings; a workspace owner owns every non-personal container (`WORK-008`). Anyone else is refused. - **Actions.** A rule's action is `unverify` or `flag` and is fixed by its kind: `cited-changed` unverifies, `no-owner` and `unviewed` flag. Any other action, "verify" first of all, is refused with a 400 problem before anything is stored. - **Unverify** ends the page's latest verification as lapsed: the run moves that verification's expiry to the run time (never later, so it never extends one), and the one shared definition of current, changed and lapsed (`STAT-003`, `STAT-004`) then reads it lapsed in the page, the review list, search, content queries, AI answers, exports and publishing. It writes no verification row and sets no status; the original verification (verifier, revision, time) stays in history and its previous expiry is kept in the activity entry. In the same batch it marks the `STAT-004` lapse notice sent, so the owner gets the run's one notice and no second lapse notice. - **Cites.** A page cites another page when its body links to or mentions that page, by the same link scan as the page's backlinks. `cited-changed` fires when a cited page (not deleted or trashed) has a working revision created after the citing page's latest verification, and that verification still reads current. - **No owner.** The page's owner is unset or names a member who is no longer active. It applies to every live page of the container, verified or not. - **Unviewed.** No page view in the last N days (180 by default, 1 to 3650) while the page's verification reads current. - **A flag** is a marker on the page's status panel and in the container's rules panel. It is not verification and does not change search ranking or any trust badge. It is removed when its condition clears; the page's owner or a container owner can dismiss it, and a dismissed flag stays dismissed while its condition holds. - **Nightly, exactly once.** The run is part of the Worker's own schedule in every profile. Each rule runs once per UTC night, with a durable receipt per rule and night; concurrent cron or queue invocations and a restart produce one run's effects. A rule turned on runs from the next night, never the night it is turned on. - **Recorded.** Each changed page (unverified, or newly flagged) gets one activity entry with the system as actor, naming the rule and why (the cited pages, the missing owner, the days unviewed) and never page text; it shows only to members who can read the page. - **One notice.** Each affected owner (the page's owner while an active member, else the container's owners) gets exactly one `verification-rules` inbox item per run, with counts and page titles only for pages that recipient can read. - **Preview** runs the same selection and writes nothing; pages the previewer cannot read are counted, not named. The rules panel offers it before a rule is turned on and for a rule already on. "A source it cites" has no block kind in the default product: connected sources are flagship-only. Every existing capability (a cited page) conforms now, and the obligation is inherited: when `SOURCE-003` (scoped claims) and `SOURCE-004` (live observations) ship, a change to a source that a page cites unverifies that page through this same `cited-changed` rule.
