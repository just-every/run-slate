# Source and delivery

The 10 October 2026 decision in CONTRACT.md supersedes T-092's native-auth implementation exemption. Slate retains own accounts, sessions and roles, including existing member IDs, group memberships and scoped guests. Base identity and dependency protocols must compose through the native accounts adapter without a second owner ledger. Base signs people in through the mounted native accounts and proof adapters; Slate retains its member and session records. Applied migrations remain preserved. Hosted installation and edit publication still need stage evidence and the owner's production approval.

Byte-exact Base exports and retained origin evidence are recorded in `base-copies.json`, `edition.json` and `sources.lock.json`. Do not alter shared bytes locally; correct upstream source and repin. Root `rer-setup.json` defines application answers and secrets. Hosted mailbox bootstrap uses ordinary magic links; local setup preserves generated settings, and `rer dev` opens a key-gated owner session with mail suppressed. Deployment uses Base deploy-kit with `deploy.json` and explicit mail credentials.

After changing source, build, run `pnpm integration:sync`, stage intended files, run `pnpm source:lock`, then commit. `pnpm source:check` checks the source lock and the integration generated from the emitted Wrangler config through Base's spec reader. `pnpm artifact:delivery` writes a fresh schema-2 output directory containing the descriptor and raw payloads; each has its size and SHA-256. Existing output directories are refused. Build provenance remains in `.cache/slate/build-source.json`; the producer is untrusted input to independent workflow attestation.

`rer-project.json` and `.github/workflows/rer-managed.yml` are generated from the same packaging policy. The descriptor's setup digest binds the committed root manifest. The public identity remains `just-every/run-slate`; this private source work does not publish a release or update the existing public tag.

`pnpm publish-check` runs verify, operations description and publication-input validation. Full-history publication hygiene and `rer release --dry-run` also run through Base's release tools at the recorded main pin. A passing local artifact check does not establish trusted workflow attestation, provider acceptance or hosted admission.

`pnpm test:delivery-artifact` validates every schema-2 payload size/digest, applies its original SQL, and runs only the packaged Worker/assets against local D1/R2/Queues. The retained checks cover unconfigured refusal, native email-confirmation/session sign-in with substitution only at the test mail transport edge, first run, editing, search, export, profile refusal and exact asset bytes. Test identity records do not establish remote mailbox possession or provider delivery.

The optional editor uses server bindings `RER_MANAGEMENT_ORIGIN` and `RER_INSTALLATION_ID`. Both must form valid installation configuration; unconfigured installations have no mount. `/api/editor/config` authenticates a current native session and requires its owner role, returns only nonsecret configuration with a 30-second grant, and uses no-store. The shell refreshes on focus and every 20 seconds, removes the mount on transport-observed logout/session denial and unmount, and expires unseen server-side changes at the lease boundary. Compiled edits install before hydration and destination leaves mark readiness. HTTP CSP retains existing policies and limits frames and ancestors to self and the configured management origin. The fixture provider in the browser tests proves local allow/deny and protocol behavior; actual management registration and source → build → hosted reload remain stage work.
